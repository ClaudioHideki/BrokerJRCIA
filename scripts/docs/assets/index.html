Comece por aqui

  1. A JRC fornece a URL desta instalação, sua organização e uma chave com os escopos contratados. O endereço do seu sistema não é necessário para emitir essa chave.
  2. Use X-JRC-API-Key. A chave determina o tenant. Não envie organizationId para escolher outra empresa.
  3. Escolha o perfil abaixo e clique em Authorize para informar a chave. Use apenas uma forma de autenticação por requisição. A autorização fica somente na memória desta aba.
  4. Para receber mensagens e status no seu sistema, configure posteriormente o webhook HTTPS do seu backend. No Chatwoot, um adaptador deve transformar esses eventos em contatos, conversas e mensagens locais.
O que cada perfil faz e como validar a POC

Conexões: listar e consultar instâncias; criar, parear e desconectar com instances:write. O pareamento usa números de homologação escolhidos por você.

Mensageria: contrato específico de leitura/envio por chave. Não presuma que a chave de instâncias possui esses escopos. Uma resposta 202 significa aceitação, não entrega; acompanhe o estado e preserve a mesma Idempotency-Key ao repetir a mesma intenção.

Integração direta Chatwoot: opção para o Broker acessar uma Account remota. Usa chave de controle vinculada e exige destino previamente configurado. É diferente de um sistema que consome a API JRC e recebe eventos no próprio backend.

POC: começar com um número, comprovar entrada, resposta, estados, duplicatas, revogação e isolamento; expandir até cinco números. Os quinze dias começam após o aceite inicial. Nenhum teste desta página é automático.

Módulos nativos: instalar a tela de QR/Flow dentro do Chatwoot exige o pacote adaptado à versão do host. A documentação da API não instala módulos. Flow usa permissões e registro próprios.

Resultado incerto: UNKNOWN ou timeout exige consulta/conciliação; não troque a chave idempotente para forçar novo envio. Os limites e formatos aceitos são os dos schemas exibidos abaixo.
